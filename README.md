# ASCIIpaint 字元畫板

在 Canvas 上畫圖，即時轉成 ASCII Art（點字、混合、方塊、濃淡、圓點、中文、線段、自訂字元），
並以純文字 / 彩色 HTML / ANSI 複製，方便預覽在不同平台貼上的效果。

## 開發

需要 Node ≥ 22 與 pnpm。

```bash
pnpm install
pnpm exec playwright install chromium   # 只有跑瀏覽器測試才需要
pnpm dev            # 開發伺服器（Vite）
pnpm build          # 型別檢查 + 打包到 dist/
pnpm preview        # 預覽打包結果
pnpm test           # 全部測試
pnpm test:unit      # 單元測試（Node）
pnpm test:browser   # 瀏覽器測試（Vitest browser mode + Playwright Chromium）
pnpm lint           # ESLint
pnpm format         # Prettier
pnpm typecheck      # tsc --noEmit
```

若瀏覽器測試因缺少系統函式庫而無法啟動（WSL 常見），執行
`sudo ./node_modules/.bin/playwright install-deps chromium`。

## 結構

```
index.html          頁面標記（無內嵌 style / script）
src/
  main.ts           進入點：載入字型與樣式、初始化各模組、啟動繪製迴圈
  state.ts          共用的可變狀態（工具、模式、畫布尺寸、轉換結果）
  types.ts          Mode / Palette / Metrics 等共用型別
  convert.ts        畫布像素 → 每格一個字元（純函式，不碰 DOM）
  blocks.ts         方塊字元（濃淡、象限、八分之一）的矩形定義與解析墨量向量（純函式）
  match.ts          每格 2×4 墨量與候選字的比對、點字候選合成（純函式）
  glyphs.ts         字形墨量校準（依實際字型量測，字型或格寬改變時須清快取）
  charsets.ts       各模式使用的字元表
  color.ts          sRGB 亮度計算、hex 工具（純函式）
  theme.ts          讀取 CSS 變數
  surface.ts        畫布 / 暫存層、格寬量測、視窗縮放
  render.ts         將轉換結果畫到螢幕（點字、方塊、圓點、文字）
  draw.ts           指標事件：自由筆跡、拖曳圖形（預覽用還原基底）、文字工具的點擊
  shapes.ts         直線、圓、方的繪製（外框矩形、純函式部分可測）
  text.ts           文字工具：單行輸入框、即時預覽、確定／取消
  brush.ts          筆寬計算（筆跡與預覽圓圈共用，純函式）
  grid.ts           欄列數的範圍、夾限、緩衝尺寸與縮放計算（純函式）
  platforms.ts      各平台字數上限、計數規則與建議尺寸推算（純函式）
  history.ts        復原 / 重做
  sample.ts         把起始畫面（DRAW / TEXT）畫進緩衝
  sampleLayout.ts   起始畫面的版面（純函式：置中、等寬對齊）
  font.ts           起始畫面用的 7×7 等寬點陣字（每個字母左右欄都有墨，寬度一致）
  export.ts         純文字 / HTML / ANSI 輸出（純函式）
  ui/               工具選取（tools.ts）、工具列、複製選單、提示訊息、筆刷範圍圓圈（brush.ts）、畫布大小（canvasSize.ts）、顯示／收起動效（reveal.ts）
  styles/           tokens（主題色）/ base / brush / shell / controls / tray / overlays
tests/
  unit/             Node 環境：export、color
  browser/          真實 Chromium：convert、parity
legacy/             重構前的單檔版本，僅供對照測試使用
```

## 動效

點了才出現的區域（複製選單、畫布大小面板、自訂字元列、兩個 ⓘ 提示框、toast、剪貼簿備援面板、平台讀數）都由 `src/ui/reveal.ts`
以 Web Animations API 做進出動效：會推擠版面的區塊以高度滑動＋淡入（展開約 200 ms、收起約 150 ms），toast 由上方滑入，提示框由下方滑入，其餘淡入淡出。

- 滑動期間畫布會先凍結（維持原清晰度，下緣被漸漸裁切或露出），動畫結束後才重算一次格數，所以不會每幀重新轉換。
- 系統開啟「減少動態效果」時完全不播放，維持瞬間切換。
- 收起時 `hidden` 屬性要等動畫結束才設定；程式碼判斷是否開啟請用 `isOpen()`，不要直接讀 `hidden`。
- 測試以 `app.settle()`（等所有動畫結束）取代固定等待。

## 工具

- **繪製／擦除**：自由筆跡；擦除寬度是粗細的 2.5 倍。
- **直線、圓、方**（色票列下方的圖示列）：按住拖曳，放開確定；拖曳中會即時預覽成字元，`Esc` 取消，只點一下不會留下復原步驟。方是以兩個對角拖出的矩形，圓是這個矩形的內切橢圓（拖成正方形就是正圓）；只有外框，線寬是「粗細」，顏色是目前筆色。
- **文字**：點一下畫布，上方出現單行輸入框，邊打邊在畫布上預覽；`Enter` 確定、`Esc` 取消，切換工具也算確定；選到文字工具時右側出現「字級」滑桿（12–160 px）。字型固定為 IBM Plex Mono 粗體（中文自動用 Noto Sans TC）。文字是畫進畫布的像素，之後和其他筆跡一樣會被轉成字元、可擦除與復原。字小時轉成字元後不易辨認（點字模式比方塊模式清楚），需要夠大的字級。
- 未做：曲線、填滿、Shift 約束、多行與再編輯文字、鍵盤快捷鍵。

## 轉換模式

| 模式                             | 用到的字元                                                                                                                                                                                          |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 點字                             | 點字（固定門檻；灰階以 Bayer 抖動）；**預設模式**，放在最前面                                                                                                                                       |
| 混合                             | 方塊（`█ ▀ ▄ ▌ ▐` 與象限組合）、濃淡（`░ ▒ ▓`）、八分之一方塊（`▁▂▃▅▆▇`、`▏▎▍▋▊▉`）、點字；不含任何 ASCII 符號。以字型實際繪出並量測墨量，用每格 2×4 的墨量分佈挑最接近的字，細線與淡邊緣會變成點字 |
| 方塊                             | 同上方塊類（不含點字），自繪矩形、不依賴字型，同樣以墨量比對                                                                                                                                        |
| 濃淡 / 圓點 / 中文 / 線段 / 自訂 | 各自的字元表，依整格墨量挑選（線段會依筆跡方向挑 `- \| / \\`）                                                                                                                                      |

方塊與混合的調整參數集中在 `src/match.ts`：`BLANK_BELOW`（低於此墨量留白）、`BRAILLE_MIN`（點字最低墨量）、`TONE_WEIGHT`（整格濃度誤差的權重）。

方塊類八分之一方塊只有「貼底」與「貼左」的長條，中段的細水平線在「方塊」模式沒有對應字，
會被挑成最接近的 `▏`（一排小豎條）或留白；「混合」模式則會改用點字表現。

## 畫布大小

「畫布大小」區塊（工具列，預設收合）：

- **自動**（預設）：欄列數依視窗大小決定。
- 關閉自動後可指定欄 8–200、列 4–100。畫布維持固定格數，等比縮放置中塞進視窗；改變格數時已畫內容會跟著縮放。
- 格數變更可復原／重做；復原快照總量上限 128 MB，格數很大時可復原的步數會少於 50 步。
- 格數越大，每次重繪越慢（無頭 Chromium 實測，繪圖時單次重繪最慢的混合模式：約 60×23 格 20 ms、120×60 格 32 ms、200×100 格 78 ms）。

## 目標平台

「畫布大小」區塊的「平台」選單：選擇後套用該平台的建議尺寸（會關閉自動、可復原），並顯示「已用 / 上限」，
計算的是複製純文字時實際會貼出去的內容（含空白替代與 ``` 區塊）。之後手動改欄列數不會取消目標平台，讀數持續對照該平台上限；
超出時以紅字標示，複製純文字時 toast 也會提醒（內容仍會複製）。

選單本身只用來選擇（清單中不分組、不標來源）；每個平台的上限、計法、資料來源（官方文件已確認／第三方來源未經官方確認）與建議尺寸，
都在選擇器旁的 ⓘ 提示框裡，點一下開關。選「自訂」時沒有目標平台，ⓘ 隱藏。

**聊天室**是清單最前面的通用項目：套用 24 × 12，比發文更保守（聊天泡泡通常更窄、更容易換行）。
它不對應單一平台，所以沒有字數上限、不顯示讀數；24 是估計值，非官方數字，請在實際聊天軟體實測後調整。

| --------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| X                     | 280                              | 加權：U+0000–10FF、2000–200D、2010–201F、2032–2037 算 1，其餘（含方塊、點字、中文）算 2；換行算 1 | 官方：[X 計數說明](https://docs.x.com/fundamentals/counting-characters)、[twitter-text 設定](https://github.com/twitter/twitter-text/blob/master/config/v3.json) |
| Telegram              | 4096                             | 字元                                                                                              | 官方：[Bot API](https://core.telegram.org/bots/api)（`sendMessage.text`：1-4096 characters after entities parsing）                                              |
| Discord               | 2000                             | 字元                                                                                              | 官方說明文：[support.discord.com](https://support.discord.com/hc/en-us/articles/33694251638295)（只取得搜尋摘要，頁面本身無法直接抓取）；Nitro 的 4000 未納入    |
| Mastodon              | 500                              | 字元                                                                                              | 官方：[發文說明](https://docs.joinmastodon.org/user/posting/)；500 是預設值，各站可調整                                                                          |
| Instagram 說明 / 簡介 | 2200 / 150                       | 字元                                                                                              | 第三方來源，未經官方確認                                                                                                                                         |
| Threads               | 500                              | 字元                                                                                              | 第三方來源，未經官方確認                                                                                                                                         |
| LINE                  | 5000                             | UTF-16 單位                                                                                       | 第三方來源，未經官方確認                                                                                                                                         |
| Bluesky               | 300 graphemes（另有 3000 bytes） | grapheme                                                                                          | 第三方來源，未經官方確認                                                                                                                                         |

**建議尺寸**：欄數 ≈ 列數 × 2（格子約 1:2，畫面近似正方形），取最大且「每格都是權重最高的字元（方塊或點字）加上換行」也不超過上限的列數，
列數最多 16、欄數最多 32。結果：X 與 Instagram 簡介 16 × 8、Mastodon 與 Threads 30 × 15、Bluesky 24 × 12（最壞情況只剩 1 個字元餘裕）、
其餘（Telegram、Discord、LINE、Instagram 說明）32 × 16。

**沒有可信資料、因此未納入的項目**：各平台聊天泡泡的換行寬度、顯示字型大小與可顯示行數。欄數上限 32 是估計值，
非官方數字；實際貼出後仍可能折行，請在目標平台實測後調整。Telegram 的換行是否算 2 個字元、X Premium 與 Discord Nitro 的長文額度亦未納入。
平台規則變動時，只需更新 `src/platforms.ts` 的資料。

## 對照測試（tests/browser/parity.test.ts）

同時載入 `legacy/index.html` 與目前版本，餵入相同的筆跡與操作，逐項比對
6 種模式（點字、濃淡、圓點、中文、線段、自訂）× 色彩 / 灰階 × 亮 / 暗主題 × 3 種複製格式、筆跡底圖、空白替代與程式碼區塊，
並比對畫布像素是否一致。
舊版的起始畫面是 ASCII / PAINTER、新版是 DRAW / TEXT（刻意不同），所以兩邊都先按「清空」再開始比對。
「混合」與「方塊」的字集在重構後刻意重新設計，輸出與舊版不同，所以不在比對範圍內（由 `tests/unit`、`tests/browser/convert.test.ts` 直接驗證）。
新版多了一列「畫布大小」，畫布區域較矮，所以測試會先把舊版頁面調到相同的畫布高度再比對。重構期間用來確保行為不變；之後若刻意改變行為，更新或移除 `legacy/` 即可。

## 已知問題（重構時發現，未修改）

- 圓點模式最淡的圓點（`·`）轉換後會被「折回 ASCII」成 `.`，導致畫面上不會畫出該級圓點，
  輸出也是 `.`（`src/convert.ts` 結尾的 `·` → `.` 取代作用在所有走到該處的模式）。
- 自訂字元若包含 `·` 也會被同一段取代成 `.`。
